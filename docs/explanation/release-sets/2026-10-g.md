The VS Code extension is not part of this set and nothing in it changed.

## What differs from the 0.14 set

* The publish order and the five packages are the same.
* **`reference/components/` and `reference/ecosystem-ci/`** are in the tree. They are not published and not in the workspace. `components/` has no lockfile on the branch until the release (a registry-only lockfile cannot exist before the packages are on npm).

## Before tagging

1. Merge the release branch; CI is green on it.
2. `npm view @valancex/valance@0.15.0 version` is a 404 for each of the five.
3. `PORT_REF` in `.github/workflows/release.yml` still names `v0.14.0` (PORT is unchanged).
4. Run the workflow as a dry run from the branch (`publish` unticked) and read `conformance` and `budgets`.

## After the tag

1. `npm view` each of the five at 0.15.0.
2. Make the two repositories from `reference/` and run the ecosystem CI with `tag: 0.15.0` (see the notes).
3. Mark the notes "released"; set `PUBLISHED` in `scripts/measure-footprint.mjs` to 0.15.0.
