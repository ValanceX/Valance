MESH and PORT are not part of this set. PORT's published packages (`@valancex/port-web`, `@valancex/port-desktop-vocabulary`) do not use Effect and are unchanged at 0.15.0; PORT's private `integration/` package moved to Effect 4, NEXUS `^0.18.0` and MESH `^0.18.0` (ValanceX/Port#33). The VS Code extension is not in the set.

## What differs from the 0.16 set

* **Two repositories, not four.** Only NEXUS and VALANCE changed.
* **One local pack, not five.** The VALANCE and PORT branches installed NEXUS from `local-packs/` through a `pnpm-workspace.yaml` override, in one commit each marked "DO NOT MERGE BEFORE THE RELEASES"; both were reverted after NEXUS 0.18.0 was published, before merging.
* **A breaking change authors must make.** Effect 4's `Schema.Literal("a", "b")` silently keeps only `"a"`, which is why `vlx check` now reports it (`effect-v3-schema`).

## Before tagging VALANCE (done)

1. NEXUS 0.18.0 is on npm.
2. The pack commit is reverted; `pnpm install` wrote the registry lockfile; build, typecheck, lint and `pnpm -r test` pass.
3. `npm view @valancex/valance@0.17.0 version` was a 404 for each of the five.
4. `PORT_REF` in `.github/workflows/release.yml` stays `v0.15.0`: PORT has no newer tag.
5. The workflow ran as a dry run from the branch, and `conformance` and `budgets` passed. `budgets` did not measure the previous release (0.16 is on Effect 3, which the tree's example cannot build against), so the wall-clock ratio gates were reported, not gated, for this release only.

## After the tag

1. `npm view` each of the five at 0.17.0 (done).
2. `PUBLISHED` in `scripts/measure-footprint.mjs` is 0.17.0 on Effect 4.1.0 (ValanceX/Valance#37), so the next release's `budgets` job measures against it.
3. Not done, on purpose: the `reference/` repositories' ecosystem CI with `tag: 0.17.0` is the maintainer's next run; the dev pin stays at Effect 4.1.0 (4.1.2 is now `latest`; the `^4.1.0` ranges already accept it).
