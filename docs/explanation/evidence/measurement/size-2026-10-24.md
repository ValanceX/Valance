# Size analysis, 2026-10-24 (W23a for the ceilings of WP8)

The ceilings of the [2026-10-17 `vlx build` baseline](../../baselines/2026-10-17-vlx-build.md) were set from a counter that had a sixth of today's features. WP8 turns them into gates, and the first measurement ([2026-10-24, before WP8](../../baselines/2026-10-24-wp8-before.md)) is over four of them. W3 says a ceiling moves only as a recorded decision; W23a says it needs a size analysis. This is that analysis. It explains the growth since the baseline, says what is a cost of a feature and what could be cut, and is the file `analysis` points at for each raised ceiling in `packages/cli/src/budgets.json`.

| Metric (brotli) | 2026-10-17 baseline | Old ceiling | 2026-10-24 | Growth | New ceiling |
|---|---:|---:|---:|---:|---:|
| `mesh-runtime.wasm` | 170,828 | 179,400 | 183,629 | +12,801 (+7.5%) | 192,900 |
| Counter JavaScript | 87,918 | 92,400 | 93,722 | +5,804 (+6.6%) | 98,500 |
| `docs-app` JavaScript | 92,708 | 97,400 | 98,520 | +5,812 (+6.3%) | 103,500 |
| Counter, all files transferred | 261,005 | 274,100 | 279,594 | +18,589 (+7.1%) | 293,600 |
| Counter CSS | 80 | none | 1,053 | +973 | 1,200 (new) |
| `docs-app` CSS | 634 | none | 1,542 | +908 | 1,700 (new) |

The new ceilings are the 2026-10-24 figures plus 5 percent, rounded up to the next 100 (the next 10 under 1,000), which is the rule of W3 applied to a new baseline. Nothing is raised by more than the growth explained below.

## The WebAssembly runtime: +12.8 kB, all of it language features

Measured by section on the published runtimes (the module's own bytes, brotli per section; `node` script in the commit message of the budgets change, `sections.mjs`):

| Runtime | Raw | Brotli | Code section (brotli) | Data section (brotli) |
|---|---:|---:|---:|---:|
| 0.12.0 (baseline) | 765,371 | 170,828 | n/a | n/a |
| 0.13.0 | 765,734 | 170,995 | 147,999 | 20,586 |
| 0.14.0 | 818,101 | 181,627 | 157,783 | 21,550 |
| 0.15.0 (what VALANCE uses) | 732,005 | 183,629 | 158,988 | 22,150 |
| 0.16.0 | 731,768 | 183,410 | 158,920 | 22,129 |

- **0.13 to 0.14: +10.6 kB.** The code section grew 9.8 kB and the data section 1.0 kB. MESH 0.14 added enums, the `has` operator, `??` and defaults to the language (W23: "the compiler WebAssembly grew from 296,029 to about 309,000 with enums, `has`, `??` and defaults"). The runtime carries the checker and the evaluator for them.
- **0.14 to 0.15: +2.0 kB.** State units (`raise`, the unit scope) and snippets. The code section grew 1.2 kB and the data 0.6 kB. The raw module is 86 kB smaller (wasm-opt `-O2`, W27) and the compressed one is larger: the optimizer removed bytes that compressed well. This is W2 again (raw size rewards the wrong change).
- **0.15 to 0.16: -0.2 kB.** No runtime change.

Could it be cut? `twiggy` on the compiler found no single avoidable item (W23a, [compiler-size.md](compiler-size.md)); the runtime is the same code base and the same finding holds. Two things are left to try, and both are MESH work: compare `-Oz` and `-O2` on the *brotli* size of the module (W27 measured 3.0 percent for `-O2`, in a release that also changed the language), and drop the diagnostics' message tables from the runtime build. Neither is in WP8, and neither is needed to hold the new ceiling, which is where the module is.

## JavaScript: +5.8 kB, in the packages that grew with the features

The counter's JavaScript is the ecosystem's packages and Effect. Effect is unchanged (about 230 kB raw in `docs-app`, 70.5 percent of the 326,703 bytes the source map attributes; it was 229.8 kB, 75.2 percent, in the first baseline). The growth is the ecosystem's share, which went from about 75.8 kB to 96.5 kB raw in `docs-app` (434,216 bytes in all against 410,264):

| Package, `dist` JavaScript, unminified | Before | Now | Brotli before | Brotli now |
|---|---:|---:|---:|---:|
| `@valancex/port-web` 0.6.1 to 0.12.0 | 61,770 | 93,039 | 13,400 | 19,334 |
| `@valancex/valance` 0.13.0 to the tree | 77,999 | 113,681 | 19,903 | 28,019 |
| `@valancex/common` 0.13.0 to the tree | 74,932 | 128,119 | 19,001 | 28,727 |
| `@valancex/nexus` 0.12.3 to 0.14.0 | 44,558 | 46,089 | 11,093 | 11,431 |
| `@valancex/mesh-runtime` JavaScript 0.12.0 to 0.15.0 | 54,524 | 59,313 | 12,511 | 13,316 |

These are whole packages, with entries a page never loads (the server, the native host, replay), so they overstate what reaches a page; the page's share by source map (`docs-app`, 326,703 bytes mapped) is `port-web` 30.2 kB, `common` 24.6 kB, `valance` 18.1 kB, `mesh-runtime` 15.0 kB, `nexus` 7.4 kB. What grew, by cause:

By file (raw bytes of the published `dist` against the tree's; the files only a build or a server loads are marked):

| Package | File | Before | Now | Growth | What it is |
|---|---|---:|---:|---:|---|
| `port-web` | `port.js` | 37,301 | 59,037 | +21,736 | the layers (`dialog`, `popover`), the radio group, focus and the nested-modal refusal |
| `port-web` | `check.js` | 10,418 | 17,126 | +6,708 | the hydration check's classes of mismatch (a server or test path) |
| `common` | `form.js` | 0 | 20,884 | +20,884 | forms (`Form`, `field`, the first-invalid focus) |
| `common` | `primitives.js` | 4,684 | 22,866 | +18,182 | the primitive table, generated from 46 specifications (it was hand-written for 32 tags, the frozen table in `packages/primitives/test/legacy`) |
| `valance` | `replay.js` | 0 | 18,309 | +18,309 | **in no page**: a separate entry, development only (a test builds a page and looks) |
| `valance` | `units.js` | 0 | 6,854 | +6,854 | state units |
| `valance` | `index.js` | 26,721 | 33,120 | +6,399 | the ledger bound (W22), the recorder hooks (no-ops without a recorder) and unit raising |

No file here is a stray dependency or dead code. **The vocabulary is shipped whole**: a counter that uses two primitives carries the realization of 46 (`primitives.js`) and `port-web` the code for all of them. A per-use table (only the tags a program names) is the next reduction; it changes how `common` builds the table and not a budget, and it is recorded as a target, not done.

## CSS: +1 kB, the default theme

The first baseline's CSS was `layout` rules only (80 bytes for the counter). Since WP4 the default theme is a stylesheet in the `vlx-theme` layer (colors, type, spacing, the buttons and fields), and since WP6 the layers' rules (modal scroll lock, popover) are in `vlx-library`: 1,053 bytes for the counter, 1,542 for `docs-app`. Zero JavaScript was added for it (the style contract's allowance, Bet 6).

## What these ceilings do not allow

Each new ceiling is the new baseline plus 5 percent, so the next feature that adds 5 percent to the runtime or to the counter fails the gate and needs its own analysis. That is the point. Two ceilings are not raised: the JavaScript heap after 200 updates (4,575,160 against 4,630,800) and the WebAssembly memory (ratcheted *down* to 1,376,300 for the counter and set at 2,408,500 for `docs-app`, now that W21 made the memory flat).
