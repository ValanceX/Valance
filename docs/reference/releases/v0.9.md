# VALANCE v0.9 release notes

## v0.9.0

*Released 2026-10-13 as v0.9.0.* A minor release of `@valancex/valance`. Before 1.0 a minor version is a new range. **It moves to MESH 0.11, which retires the structural elements: an application that uses `mesh-if`, `mesh-each` or `mesh-switch` rewrites that markup as blocks.**

### Why a minor

MESH 0.11 writes conditional and repeated structure as syntax (`{#if}`, `{#each}`) and rejects the elements it used to be written with. VALANCE derives a manifest for the templates it renders, so the derived model changes with it, and the supported MESH range moves from `^0.10.0` to `^0.11.0`.

### What changed

- **Blocks replace the structural elements.** `manifest` no longer declares `mesh-if` or `mesh-each` (the constructs the blocks lower to are built in and need no declaration; a declaration an application makes by hand is used as declared and does not change the model fingerprint). A model that names a retired element (`mesh-if`, `mesh-each`, `mesh-switch`, `mesh-case`, `mesh-default`) is refused with "is not an element: conditional and repeated structure are blocks (`{#if}`, `{#each}`)…".
- **Everything else is unchanged:** `define`, `start`, `mount`, `hydrate`, `command`, `entry`, the web, server and build entries, and the runtime and template formats.
- `examples/` and the guides were rewritten to blocks. The private, unpublished `@valancex/cli` gained typed component contracts (`field`, `component(template, { props, events, uses })`, generated template types) and Windows support; neither is part of this release's public surface (see `docs/explanation/application-model/handoff.md`).

### Compatibility set

| Package | Range | Role |
|---|---|---|
| `@valancex/nexus` | `^0.12.0` | dependency |
| `@valancex/mesh-runtime` | `^0.11.0` | peer, required |
| `@valancex/mesh-compiler` | `^0.11.0` | build time only |
| `@valancex/port-web` | `^0.4.0` | optional peer |
| `effect` | `^3.10.0` | peer |

A package that depends on the MESH runtime must accept the 0.11 line: NEXUS and PORT Web widen their peer ranges to it, and until they publish that, a project resolves two runtimes. Move `@valancex/mesh-runtime` and `@valancex/mesh-compiler` to `^0.11.0` together, since a template is compiled against the runtime that renders it. This repository's lockfile is refreshed once MESH 0.11.0 is on the registry.

### Upgrading from 0.8

1. Move `@valancex/mesh-runtime` and `@valancex/mesh-compiler` to `^0.11.0` together.
2. Rewrite control flow as blocks: `<mesh-if when={a}>x</mesh-if>` becomes `{#if a}x{/if}`; `<mesh-each items={xs} as="x" key={x.id}>…</mesh-each>` becomes `{#each xs as x (x.id)}…{/each}`; a `mesh-switch` becomes `{#if}`/`{:else if}`/`{:else}`. A branch or body is one element (several are wrapped in a fragment for you), a block cannot be the whole document, and text cannot contain `{#`, `{:` or `{/`. MESH 0.11's `retired-element` error names the block to write.
3. Remove `mesh-if` and `mesh-each` from any hand-written manifest; nothing else needs to change.
