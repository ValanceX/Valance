# VALANCE v0.17 release notes

## v0.17.0

*Prepared 2026-11-06, not tagged (v0.16.0 is the latest release).* The next minor of the five packages that share one version, published together in dependency order: `@valancex/valance`, `@valancex/style`, `@valancex/router`, `@valancex/common`, `@valancex/cli`.

v0.17.0 moves VALANCE to Effect 4. **North-star tier:** the two new diagnostics are mechanism-improving diagnostics (they tell an author what Effect 4 needs, and add no public API); the rest follows Effect 4's types. **Scorecard:** no audit moves. The audits this touches are I2 (typed contracts: the same codes and messages as before, now read from Effect 4), D2 (masking: `Schema.Redacted` fields are masked as before; one case changed, see below) and E3 (no new public export), each unchanged: I2 Pass to Pass, D2 Pass to Pass, E3 Pass to Pass.

**Needs** `@valancex/nexus` `^0.18.0` (Effect 4), which is released first; `@valancex/mesh-runtime` and `@valancex/mesh-compiler` `^0.18.0` and `@valancex/port-web` `^0.15.0` are unchanged.

## Breaking

* **Effect 4.** `effect` is a peer dependency, `^4.1.0` (`@valancex/valance`, `@valancex/common`, `@valancex/router`, `@valancex/cli`), so an application and VALANCE share one Effect. Node `>=22.19`, Effect 4's own floor.
* **Schema spellings an author writes.**

  ```ts
  // before (Effect 3)                                   // after (Effect 4)
  Schema.Literal("light", "dark")                         Schema.Literals(["light", "dark"])
  Schema.Union(Schema.String, Schema.Number)              Schema.Union([Schema.String, Schema.Number])
  Schema.String.pipe(Schema.minLength(2))                 Schema.String.check(Schema.isMinLength(2))
  Schema.NumberFromString.pipe(Schema.int(), Schema.between(18, 120))
                                                          Schema.NumberFromString.check(Schema.isInt(), Schema.isBetween({ minimum: 18, maximum: 120 }))
  .annotations({ title: "Age" })                          .annotate({ title: "Age" })
  Schema.Schema<A, I>                                     Schema.Codec<A, I>
  ```

* **The form `message` annotation is a string.** `message: () => "Enter at least 2 characters"` is `message: "Enter at least 2 characters"` (Effect 4 types it as `message?: string`). A cross-field rule reports `{ path: ["confirm"], issue: "Passwords must match" }` from `Schema.makeFilter`. Form error codes, parameters and constraints are unchanged ([Forms](../../how-to/forms.md)).
* **A `Redacted` field with a decoding default** (`withDecodingDefault`, formerly `optionalWith({ default })`) is masked as a top-level field; Effect 4 has no wrapper that hid the Redacted before.

## Added

* **`effect-version`** (`vlx check`): reported at `package.json` when the installed `effect` is not 4: `effect <installed> is installed; Valance needs effect ^4.1.0`.
* **`effect-v3-schema`** (`vlx check`): reported at the call in `src/**/*.ts` for the spellings Effect 4 changed: `Schema.Literal takes one value in effect 4: write Schema.Literals([...])`, and the same for `Schema.Union` and `Schema.Tuple` without an array. A line scanner, not the type-checker: an aliased `Schema` import, a named `Literal` import and `.tsx` files are not seen. Both are listed in the [CLI README, Diagnostics](../../../packages/cli/README.md#diagnostics). Test: `packages/cli/test/effect-v4.test.ts`.

## Fixed

* **The history follower** no longer loses a URL entry when a navigation follows `Web.run` immediately: its subscription to the state stream was made late (Effect 4 starts a forked fiber when its parent yields). It is now one queue fed by a fiber that starts at once (`packages/valance/src/web.ts`).
* `inApplication` installs its interrupt handler under `uninterruptibleMask`, so a caller interrupted right after the command starts no longer leaves it running.

## Behavior

* **Equal-valued states are still presented.** The render dedupe stays `===` (an equal-valued new state is presented, as contract v1 says and as under Effect 3), although Effect 4's `Equal.equals` is structural and would skip it; comparing structurally cost at most 1.05x for a real change at 10,000 items, so it is a contract question, not a speed one (see the migration plan, "Outcome: the render dedupe"). Test: `packages/valance/test/incremental.test.ts`.
* A subscriber of the state is woken inside the commit, and a forked fiber starts when its parent yields; code that relied on Effect 3's ordering sees the render before the next statement of the command.

## Upgrading

Move the application to `effect@^4.1.0` on Node 22.19 or later, run `vlx check` (it names the Schema spellings and an Effect that is not 4), and change the spellings in the table above. Update `message` annotations to strings. Nothing else in VALANCE's own API changed.
