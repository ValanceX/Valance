# VALANCE v0.14 release notes

## v0.14.0

*Prepared 2026-10-24 (nothing tagged or published: v0.13.0 is the latest release).* A minor release of five packages that share one version and are published together, in this order (each depends only on ones before it): `@valancex/valance`, `@valancex/style`, `@valancex/router`, `@valancex/common`, `@valancex/cli`. Before 1.0 a minor is a new range. It needs MESH 0.15 or later (0.17 for generated UI), NEXUS 0.14 or later and, for the behavior of lists, radios and layers, PORT Web 0.11 and 0.12 or later (ranges below); the releases of MESH 0.17.0, NEXUS 0.16.0 and PORT 0.14.0 are out.

**In short:** a component can hold state for one occurrence of itself (units) and a form is built from its schema; the look of an application is a theme, data checked against the Design Tokens format and WCAG contrast, with a default for free; dialogs and popovers; every control is checked for a name; a session can be recorded and replayed; a page keeps the taps a person makes before it is ready; a build prints what it ships and holds it to budgets; and a model can write the interface and have it checked as it arrives. There are renames, and three of them touch code written for 0.13 (see [Upgrading](#upgrading)).

### `@valancex/router` 0.13.1

`@valancex/router` 0.13.1 is on npm and was never in this repository: it is 0.13.0 with one change, its peer range `@valancex/valance` `^0.13.0` where 0.13.0 said `^0.12.0` (the two tarballs' `dist/` and README are identical, checked). The repository still said 0.13.0 and `^0.12.0`. 0.14.0 supersedes both, with `^0.14.0`. The likely cause is the publish order of the 0.13 workflow, which published `@valancex/common` (which depends on the router) before the router; the order is now by dependency.

### State and forms

- **Units (Tier 2).** A component declares state for one occurrence of itself, `unit({ state, commands })`, and its template reads it by name. It follows its row, starts again with the occurrence, is not rendered on the server and is invisible to the application. A component with no unit is unchanged. Needs MESH 0.15 and NEXUS 0.14. [Units](../use/units.md).
- **Forms from the schema (Tier 1: `Form.make(schema)`).** One schema says what is valid; the form reads it for the fields a screen needs, keeps what was typed, and decides what is wrong and when to say so, with one message per field, drafts and a server's `FieldErrors`. A failed submit takes the person to the first field in error (`focusFirstInvalid`). Judged by the Nu Html Checker and the accessible name and description computation in its tests. [Forms](../use/forms.md).
- **Enums and defaults.** A `Schema.Literal` union of strings is an enum in the manifest, so a prop's value is checked where it is written (`unknown-variant`); `field(schema, default)` writes the manifest default; a union MESH has no type for is a diagnostic at the field's line in `main.ts`, not a stack. A component's `children` and its props can be snippets (`snippet(...)`, optional with `.optional()`).

### Style and themes

- **`@valancex/style`.** A theme is data: Design Tokens Community Group 2025.10 documents (validated by the official schemas and the official 220-test suite), modes (light, dark, higher contrast), and recipes for the primitives with a closed set of properties and variants. VALANCE compiles it to a static, layered stylesheet for the web (clean under stylelint) and to resolved values for the Desktop. Contrast is checked by WCAG 2.2 for every declared pair, and a theme that fails does not build. A project with no `theme/` directory gets the default theme for the seven portable-core primitives. `button` takes `intent` (`neutral`, `primary`, `danger`) and `size` (`sm`, `md`, `lg`). `vlx theme check` prints the contrast, what each target applies and what it ignores. `escape.web.css` is the marked web-only hatch. Hover applies only where a pointer can hover. [Themes](../use/themes.md).

### Primitives, names and layers

- **`dialog` and `popover` (Tier 1).** A layer the application opens with a boolean (`open`); a dialog is modal, with focus kept inside and returned, a name required (`label`), and `dismiss` raised for Escape or a press outside, which the application decides. A popover takes `anchor`, `placement` and `mode`. A dialog inside a dialog is refused (`nested-modal`) by `vlx` and by the PORT. Needs PORT Web 0.12 for the web. [Layers](../use/layers.md).
- **New and changed primitives.** `toggle` (a button that stays pressed), `status` and `alert`; `button` takes `id`, `label`, `intent` and `size`; the web's radios are one group; a closed set in a form is a `radiogroup`; one `list` chooses its element by `ordered` (PORT Web 0.11). The web vocabulary's names follow ARIA's (see the renames).
- **Controls are checked for a name.** `vlx check` reports `unnamed-control` (a checkbox, text field or radio group with no `label` prop and none around it), `list-child`, `outside-container` and `unknown-ref` (a `describedby` that points at nothing); a component can declare the prop that is its accessible name (`name: "label"`). The generated primitive reference ([The primitives](../use/primitives.md)) and the web table are produced from the primitives' specifications, which are checked against the HTML Standard, ARIA in HTML and the accessible-name computation.
- **Focus follows identity.** After a patch, focus and the caret of the focused control are kept by key.

### Recording, replay and conformance

- **Record a session and replay it (Tier 2, development only).** `vlx dev --record` writes a log of snapshots, events and tree hashes; `vlx replay <log>` replays it by three routes that must give the recorded hashes, and `@valancex/valance/replay` is the same as code. A log holds what a person typed: it says so in its header (`containsUserData`), `vlx dev --record` warns when it starts, `vlx replay` refuses it without `--allow-user-data`, the conformance report will not attach one, and `record.redact` in `valance.json` keeps marked values out (a keyed digest stands in). A production bundle holds no recorder (a test builds one and looks). [Replay and conformance](../use/replay.md).
- **The conformance kit (`@valancex/conformance`, private, not published).** Specification verifiers (the Nu Html Checker, the accessible-name computation, aria-query, stylelint, the DTCG suite, the Web PORT in jsdom and in Chromium, a terminal PORT in another process, the Desktop's AccessKit tree, the session logs, generated UI) each run a deliberately wrong input and must find it; the report is unsigned until an accessibility maintainer is named.

### Start-up, budgets and late admission

- **The start-up path (Tier 1).** The head names the script (`modulepreload`) and the WebAssembly runtime, which the head's small shell compiles while the script downloads. `vlx build` prints the sets and what each file costs in brotli bytes; `vlx dev` prints nothing and checks nothing.
- **Budgets (Tier 2).** With nothing set, a production build is held to the framework's budgets: a warning when the start-up JavaScript and CSS pass the largest reference application's and an error at twice that (210.4 kB), and an error if the WebAssembly runtime passes 192.9 kB. `budgets` in `valance.json` sets the project's own. The bundler's chunk-size limit is no longer raised to hide its warning. The framework's own ceilings are data (`packages/cli/src/budgets.json`) held in the release; [Start-up and budgets](../use/start-up.md).
- **A tap before the application is ready is kept (Tier 1).** Every page's head carries a small script, allowed by hash in the Content-Security-Policy (no `unsafe-inline`), that keeps clicks, Enter and Escape in a field, and typed text; when the application is ready it does each once, in order, at the same node. A control that must not be done twice says `earlyInput="drop"`.
- **Late admission (Tier 2).** `admit(handle, name, { program, scope })` puts a program that arrived after start into the running application, held to the invariant `start` holds.
- **The Desktop engine is minified.** 753 kB to 398 kB raw (121 to 92 kB brotli), with names kept.

### Generated UI (Provisional, Tier 2)

`@valancex/valance/generate` lets a model write the interface and checks it as it arrives. A profile is a subset of the manifest; the prompt's vocabulary is written from it; `push` reports each mistake once, within 20 bytes of where it starts, and offers a preview only while no error stands (a fresh render, a prefix of the final page); `finish()` is exactly the check of the whole text; a correction names each mistake once, for at most three rounds; commands that change data ask a person with a prompt built from the manifest's `effect` and `title`, never from the model's words; the record holds the chunks and replays. Needs MESH 0.17 (`openSession`, and the optional `effect` and `title` of a command). [Generated UI](../use/generate.md).

### Fixes and tightening

- **A template name two components share is a compile error**; it was a silent first-wins.
- **`vlx build` fails with `runtime-duplicate`** when more than one MESH runtime resolves (a second copy of the WebAssembly module was shipped and fetched: 66 percent more bytes in the measurement). The ranges of `common`, `valance` and NEXUS now agree.
- **Each update releases the render it replaces**: WebAssembly memory no longer grows with updates (1,000 updates: 2.31 MB to 4.63 MB before, flat after).
- **`Mounted.dispatched` is bounded** to the most recent 1,000 exits (`ledger` on `mount`: a number, `Infinity` to keep every exit, `0` to record none); the number dropped is counted and a dropped failure is logged once.
- **The head keeps the elements that already say the same**: a stylesheet link removed and added again unstyled the page on each update.

### Measured

Counter application, brotli: JavaScript 94,330 B, CSS 1,096 B, WebAssembly runtime 183,629 B, everything transferred 280,844 B; docs-app JavaScript 99,096 B; one client page costs 2,471 raw bytes; after 200 updates the counter's heap is 4.58 MB and its WebAssembly memory 1.31 MB; a changed item of 1,000 rows is 202 bytes as patches. All are under the ceilings of `packages/cli/src/budgets.json`. Against the previous release measured on the same machine (medians of 3): interactive 0.96 times (unthrottled) and 0.98 times (4x CPU), first paint 1.27 times (56 against 44 ms; noise on this machine is up to 16 percent), `update` of 10,000 items 1.07 times, from changes 1.03 times.

## Upgrading

- **From 0.13:** change the versions of the five packages together (`@valancex/style` is new to you). `@valancex/router` 0.13.1 and 0.14.0 want `@valancex/valance` 0.13 and 0.14 respectively; do not mix.
- **Rename: `para` is `paragraph`, `item` is `listitem`, `quote` is `blockquote`** (the ARIA names, in the web vocabulary). **This is the change that touches 0.13 code.** A template that writes an old name gets a compile error that names the new one (`` `para` is now `paragraph` ``); change the tag, opening and closing. Nothing else about the element changes. (`olist` and `em` keep their tags; the Desktop vocabulary already used `paragraph` and `listitem`.)
- **Rename: a popover's `kind` is `mode`.** `dialog` and `popover` are new in 0.14, so no released code writes it; if you took `kind="manual"` from a pre-release, write `mode="manual"` (`` `kind` on `popover` is now `mode` ``). The word `kind` stays the input type of a `textfield`.
- **Rename: a control's `replay="safe"` and `replay="never"` are `earlyInput="keep"` (the default) and `earlyInput="drop"`.** The prop is new in 0.14 and was renamed before its first release, so no released code writes `replay`; an old spelling is a compile error with the hint (`` `replay` on `button` is now `earlyInput` ``), a test fails if it is accepted again, and `replay` now means session logs only (`vlx replay`, `@valancex/valance/replay`). It applies to `button`, `toggle`, `checkbox` and `radio`, on the web only.
- **A name two templates share is an error now** (it was the first one silently); rename one.
- **A production build can fail on a budget.** The framework's default budgets apply to a project that sets none (an error above 210.4 kB of start-up JavaScript and CSS, or a WebAssembly runtime above 192.9 kB, brotli). Set `budgets` in `valance.json` to hold your application to its own.
- **More than one MESH runtime in an install fails `vlx build`** (`runtime-duplicate`). Install one (`pnpm dedupe` or the equivalent) and keep `@valancex/mesh-runtime` to one version.
- **Content-Security-Policy:** the pages' head carries a small inline script. The headers file `vlx build` writes allows it by hash (`script-src 'self' 'wasm-unsafe-eval' 'sha256-…'`, no `unsafe-inline`). A host that serves a policy of its own instead of that file must copy the `script-src` line, or the shell is blocked and the taps before the page is ready are lost, as in 0.13.
- **Nothing else is required.** Units, forms, themes, layers, recording and generated UI are opt-in.

## Release steps (the maintainer's)

1. Merge when CI is green. The first real run of the release workflow's `conformance` and `budgets` jobs on a runner is the proof of decision R17; read their result before tagging.
2. Tag `v0.14.0`. `release.yml` publishes the five packages in dependency order with provenance and makes the GitHub release; it needs the `NPM_ACCESS_TOKEN` secret (an npm granular token for `@valancex`; it expires, and `@valancex/style` is a first publish, so the token must be allowed to create a package).
3. On the registry: `npm view @valancex/valance@0.14.0 @valancex/style@0.14.0 @valancex/router@0.14.0 @valancex/common@0.14.0 @valancex/cli@0.14.0 version`.
4. In an empty directory: `npm install -g @valancex/cli && vlx init demo --web --yes && cd demo && npm run build`; the project passes `vlx check`.
5. Mark these notes "released", update `scripts/measure-footprint.mjs` (`PUBLISHED` is the previous release the budgets are compared with: 0.14.0) and the "newest set installs together" row, and rerun the budgets once.
