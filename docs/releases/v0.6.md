# VALANCE v0.6 release notes

## v0.6.0

*Not yet released.* A minor release of `@valancex/valance`. Before 1.0 a minor version is a new range.

### Why a minor

It adds public API (`ValanceError`, `isValanceError`, `isRefusal`), moves the NEXUS range to a new minor (`^0.11.0`), and changes two behaviors that the contract described: a start-time command's failure is now logged, and a finished event dispatch no longer stays in a mount's `pending` list.

### What is new

- **Defects have a stable identity.** VALANCE's own defects are a `ValanceError` with a `code`: `admission-closed` (the application is draining), `application-ended` (`mount`/`hydrate` after the application ended), `not-an-application`, and, for mistakes, `bare-command-binding`, `unknown-view`, `target-not-drawn`. `isRefusal(defect)` is true for work turned away because the application or the NEXUS runtime under it is closing, ended or was never started, and false for a bug, so a command that races a shutdown no longer matches on message text. Messages are unchanged. The rule: a dying error carries `code`; a typed failure carries `_tag`.
- **A failing start-time command is logged.** `Effect.logError("start-time work failed", cause)`, as a failed popstate already was. Success, interruption by the application closing, and a refusal are not logged. There is still no channel, hook or option: the state is the way the screen hears about it. The log carries the whole cause and VALANCE does not redact it; see [API stability](../stability.md#what-is-logged).
- **A finished dispatch leaves a mount's `pending` list.** A page that never calls `settled` no longer holds every event's fiber for the life of the mount. The ledger (`dispatched`) is unchanged and still append-only. `settled` waits for what is still running, as before.
- **[API stability](../stability.md):** what each entry promises. `./internal` is stated to be Internal.

| `effect` | `^3.10.0` | peer |

### Upgrading from 0.5.0

- Nothing in an application has to change. The new NEXUS range is `^0.11.0`, which adds `Runtime.Refusal` and changes no existing NEXUS behavior.
- An application that matched the text `VALANCE: admission is closed (draining)` or `NEXUS: ...` can use `isRefusal` instead.
- An application whose start-time command can fail will now see a log line for it.
