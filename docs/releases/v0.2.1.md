# VALANCE v0.2.1 release notes

## v0.2.1

*Prepared, not yet released: the tag, the date and the npm publication follow the maintainer's tag.* A patch release of `@valancex/valance` that corrects its declared compatibility ranges and changes nothing else: no API, behavior, contract or source change relative to [0.2.0](v0.2.md).

### Why

0.2.0 declared `@valancex/nexus` `^0.10.1` and `@valancex/mesh-runtime` `^0.7.0`. `^0.10.1` now resolves to NEXUS 0.10.2, which depends on `@valancex/mesh-runtime` `^0.8.0`. A fresh consumer following the 0.2.0 install recipe therefore installed two MESH runtime copies: its own 0.7.x, and the 0.8.x nested inside NEXUS, which is the copy `Mesh.host` renders with. Before 1.0 a minor version is a new range, so the two never merge.

### Compatibility set

| Package | Range | Role |
|---|---|---|
| `@valancex/nexus` | `^0.10.2` (0.10.2) | dependency of `@valancex/valance`, and an application-level direct dependency (command definitions are written against it) |
| `@valancex/mesh-runtime` | `^0.8.0` (0.8.0) | peer, required |
| `@valancex/port-web` | `^0.2.3` (0.2.3) | optional peer, for `@valancex/valance/web` and `@valancex/valance/web/server` |
| `effect` | `^3.10.0` | peer |
| `@valancex/mesh-compiler` | `^0.8.0` (0.8.0) | build time only: compiles MPRX to the `program` each view takes |
| `@valancex/valance` | **0.2.1** | the commit this tag will point at |

With these ranges a fresh install resolves exactly one MESH runtime (0.8.0). The install commands are in [`docs/V1_CONTRACT.md`](../V1_CONTRACT.md) section 13 and the package README.

### Upgrading from 0.2.0

Install with the ranges above. `@valancex/mesh-runtime` and `@valancex/mesh-compiler` must move to `^0.8.0` together, since a template is compiled against the runtime that renders it. No application code changes.

### Validation
