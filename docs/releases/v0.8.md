# VALANCE v0.8 release notes

## v0.8.0

*Prepared 2026-10-10 (nothing tagged or published: v0.7.0 is the latest release, v0.7.1 is prepared).* A minor release of `@valancex/valance`. Before 1.0 a minor version is a new range. **Everything in it is additive; an application that changes nothing behaves as before.**

### Why a minor

It adds a public entry (`@valancex/valance/web/plugin`) and options on three existing functions. It exists so that the things VALANCE deliberately does not contain (a router, a content pipeline, a static generator, a dev server, a server adapter; see `V1_CONTRACT.md` §11) can be plugged in as packages later without re-wiring an application, and so the first of them, a documentation site, can be built on the seams now (`examples/docs-verifier`, `ROADMAP.md`).

### What is new

- **`@valancex/valance/web/plugin`.** `Plugin<S>` is a value: a `name` and any of `primitives`, `platform`, `routes`, `head`. It is passed as `plugins` to `Web.run`, `renderToHtml` or `manifest`; nothing registers on import. The rules are `V1_CONTRACT.md` §19: a tag and the URL policy are declared once (a second declaration is `plugin-conflict`, naming both owners, before anything starts); platforms merge in order and a capability provided twice is the later one's; heads merge with the application's first.
- **The document's head.** `HistoryOptions.head(state)` keeps the title, metas and links in step like `titleOf` keeps the title; `renderToHtml` takes the same function and returns `Served.head`; `renderHead` writes it as escaped HTML. A link whose `href` carries script is refused on both sides (`invalid-head`). This is what a stylesheet, a canonical URL or a social tag needs, and what a document written by hand would otherwise have to repeat.
- **`HistoryOptions.onNavigated`.** Called after a link click's URL is written and after a Back or Forward's navigate command ran, with the destination as the browser has it, `#fragment` included. Scroll and focus policy belongs here, in a plugin; VALANCE decides neither.
- **Routes and delivery.** `RouteTable<S>` carries a URL policy as one value, plus `known`, `paths` and `delivery` (`"static"`, the default, or `"server"`) for an exporter and a server. VALANCE contains neither; `deliveryOf` and `staticPaths` are the two functions an exporter needs. Static delivery is the primary path and server delivery is opt-in.
- **A waiting command can use a capability.** `command(state).waiting`'s `work` may return an `Effect` (that requires the application's environment) as well as a Promise, so a search that loads its index from the platform keeps `begin`, `wanted`, `settle` and supersession. Found by the documentation-site verifier, whose search could not otherwise reach the capability the platform provides. A Promise `work` is unchanged.
- **`primitives` is optional** on `Web.run` and `renderToHtml` (an application whose tags all come from plugins has none of its own).
- **Re-export policy** (`V1_CONTRACT.md` §19): a package built on these seams is re-exported, if at all, as its own `web/<name>` subpath with the package an optional peer. `test/tree-shaking.test.ts` bundles the source and reads the output to keep each entry's weight its own.

### Compatibility set

| Package | Range | Role |
|---|---|---|
| `@valancex/nexus` | `^0.12.0` (0.12.2 recommended: it declares `sideEffects: false`) | dependency |
| `@valancex/mesh-runtime` | `^0.10.0` | peer, required |
| `@valancex/port-web` | `^0.4.0` | optional peer |
| `effect` | `^3.10.0` | peer |

### Upgrading from 0.7

Nothing has to change. `Web.run`, `renderToHtml` and `manifest` behave exactly as before without `plugins`, `head` or `onNavigated`. `Served` gained a `head` member (`{}` when there is none); code that builds a `Served` by hand, rather than receiving one, adds it.
