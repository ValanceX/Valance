# VALANCE v0.3 release notes

## v0.3.0

*Prepared, not yet released: the tag, the date and the npm publication follow the maintainer's tag.* A minor release of `@valancex/valance` that makes one behavior change: **`start` now fails when a view declares an event that the application's command table has no key for**, and when MESH rejects a view's program. The public entries, `ApplicationHandle` (`{ state, invoke }`), `command`, `entry` and `Web.run` are otherwise unchanged from [0.2.1](v0.2.1.md).

### Why a minor

An application that started under 0.2.1 can fail to start under 0.3.0 (below). Before 1.0 a minor version is a new range, so `^0.2.1` does not pick this release up by itself.

### Start conformance (`D ⊆ B`)

- **A declared event with no command-table key fails `start`**, with no handle and nothing admitted. The failure is the typed `ConformanceViolation`, listing every missing declaration: the view, the declaring component, the event, the command, the key `component/command`, and MESH's span in that component's template source.
- **Every view is checked**, including unselected views, inactive conditional branches and repeated bodies. VALANCE asks MESH (`declaredEvents`); it reads no program. A key declared more than once is one requirement. Extra table keys (`app/...` entries, history's navigate key) are still allowed: only declared events need a key.
- **A program MESH rejects now fails `start`** with MESH's own diagnostics (`MeshDiagnostics`, the first such view in the definition's order), and conformance is then not evaluated. Diagnostics that depend on the values a scope produces are still reported when a mount renders that state.
- **`UnmappedCommand` is unchanged.** It remains the runtime defense for keys MESH never declared, history's navigate key, and a render that did not come from this application's programs.
- The check is of key presence only. It says nothing about which command an entry runs, its arguments or its success.
- Contract: [`docs/V1_CONTRACT.md`](../V1_CONTRACT.md) sections 2, 3, 10, 15 to 17, and constraint C34 in [`docs/CONSTRAINTS.md`](../CONSTRAINTS.md).

The ranges are unchanged from 0.2.1.

### Upgrading from 0.2.1

- Bind every event a view declares (or remove the event from the view). A harness that borrowed a program only to have a view should use a program that declares no events.
- A `ConformanceViolation` or `MeshDiagnostics` from `start` is now a startup failure: `Web.run` rejects with it and `renderToHtml` fails with it.
- `StartError` is wider by `MeshDiagnostics | ConformanceViolation`, and `ConformanceViolation` and `UnmappedDeclaration` are new type exports. An exhaustive `switch` over a start error's `_tag` needs two new cases.
- In a browser, call the MESH runtime's `init()` **before** `start` (previously it was first needed at mount). `Web.run` pages that already `init` first are unaffected.

### Known limits

- Only the first invalid program (in the definition's order) is reported, and its diagnostics do not name the view.
