# VALANCE v0.10 release notes

## v0.10.0

*Prepared 2026-10-13; published (on npm as `latest`, checked 2026-10-14).* A minor release of `@valancex/valance`. Before 1.0 a minor version is a new range. **No API and no behavior of the package changes: an application that changes nothing behaves as before.**

### Why a minor

`@valancex/valance` now supports **two** MESH lines, 0.11 and 0.12 (`@valancex/mesh-runtime` `^0.11.0 || ^0.12.0`), and a 0.x caret admits one minor only, so the peer range is a new range. VALANCE 0.9 supported MESH 0.11 alone.

### What changed

- **MESH 0.12 is supported** (the peer range above). MESH 0.12 adds formatting and indentation of MPRX to the language server (`textDocument/formatting`, `rangeFormatting` and `onTypeFormatting`); the runtime, the compiler and every document format are unchanged, so VALANCE has nothing to adapt.
- **The source is formatted and linted with OXC** (`oxfmt`, `oxlint`; `pnpm lint`, `pnpm format:check` in CI). A mechanical reformatting of every file and a handful of unused imports and variables removed; no exported name, type or behavior changed. The published files are the compiled output, so a consumer sees no difference.
- **Application tooling (private, unpublished; not part of this release's surface).** `@valancex/cli` gained a global `vlx` that runs the project's own install, `vlx init` (an Ink wizard that makes a new web application), an Ink interface for `dev`, `build` and `check` in a terminal (plain text everywhere else), and the editor extension formats MPRX and shows short CodeLens by default. See `docs/application-model/HANDOFF.md`.

### Compatibility set

| Package | Range | Role |
|---|---|---|
| `@valancex/nexus` | `^0.12.0` (**0.12.3 recommended**: its peer range accepts MESH 0.11 and 0.12; 0.12.2 names `^0.10.0` only) | dependency |
| `@valancex/mesh-runtime` | `^0.11.0 \|\| ^0.12.0` | peer, required |
| `@valancex/mesh-compiler` | `^0.11.0` or `^0.12.0`, the same line as the runtime | build time only |
| `@valancex/port-web` | `^0.4.0` (**0.4.2 recommended**: its peer range accepts MESH 0.11 and 0.12) | optional peer |
| `effect` | `^3.10.0` | peer |

Move `@valancex/mesh-runtime` and `@valancex/mesh-compiler` together: a template is compiled against the runtime that renders it, and the application must declare the one runtime NEXUS and PORT Web render with.

### Upgrading from 0.9

Nothing has to change. To use MESH 0.12's formatting in the editor, move `@valancex/mesh-runtime`, `@valancex/mesh-compiler` and `@valancex/mesh-lsp` to `^0.12.0` together; nothing else in an application changes.

### Verification

`@valancex/valance` 178 tests, tracer-web 553, docs-site and docs-app smoke, the VS Code extension (unit and host suites on 1.90.0 and the current VS Code), `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, all against MESH 0.11 from the registry. Against MESH 0.12 (a local build): the package tests and the extension's formatting case.
