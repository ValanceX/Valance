# VALANCE v0.16 release notes

## v0.16.0

*Prepared 2026-10-25 (nothing tagged or published: v0.15.0 is the latest release).* The next minor of the five packages that share one version. Later changes of the release are added below.

### `define` without `view` (Tier 1)

With exactly one entry in `views`, `Valance.define` no longer needs `view`: it is that view, the rule `defineApp` already follows. With more than one entry `view` is still required, and leaving it out is a type error. Additive: a definition that gives `view` is unchanged. Tier 1 (a default for what has only one answer). Audit T1.2 for the Valance column, with A4 (`learn/first-application.md` derives the manifest and now drops `view`): Partial to Pass. Test: `packages/valance/test/define-default-view.test.ts`.

### Stability coverage test (tooling)

`packages/valance/test/stability-coverage.test.ts` fails when a public entry of a published package (`cli`, `common`, `router`, `style`, `valance`, read from each `package.json` `exports`) exports a value `docs/stability.md` does not name; an `./internal` entry is checked only for its row. It found `assetPath` and `withAssets` (`@valancex/common/desktop`), `recording` (`@valancex/common/record`), `request` and `only` (`@valancex/common/http`) and `property` (`@valancex/valance/web`), now named in the stability table. `docs/use/README.md` lists every `ValanceErrorCode`, including `missing-view`. Tooling only, no API change. Audit E3 for the Valance column: Partial to Pass (every value export of a published entry now has a tier, and the test keeps it so).

### Typed `invoke` keys, `command-argument-order`, a typed `resolve` (Tier 1 for `invoke`; tooling)

* **`invoke` keys are typed.** `ApplicationHandle<S, E, K extends string = string>`: `start` reads `K` from the command table `define` was given, `"app/name"` for a bare command and an exact `"component/name"` key as written, so `handle.invoke("app/ad", …)` (a typo) is a type error. A key that is not a literal (a `string`, a template such as `` `app/${name}` ``) is accepted as before and an unknown one is still the typed `UnmappedCommand`; `InvokeKey` is the rule. `invoke` is now a method, so a typed handle is still an `ApplicationHandle<S, E>`, which takes any key, and a definition typed `ApplicationDefinition<S, E, R, V>` (the default `K`) gives one. Tier 1 (nothing to write). Test: `packages/valance/test/invoke-keys.test.ts`.
* **`vlx check` warns `command-argument-order`** where a template passes a bare command's arguments under names that are not its fields in order (`move(to, from)` for `Schema.Struct({ from, to })`). The binding stays positional ([Contract §3](../V1_CONTRACT.md#3-state-and-commands)). The first warning of the tools: a diagnostic may now carry `"severity": "warning"`, which `vlx check` prints and does not fail on (the VS Code extension shows it as a warning). Test: `packages/cli/test/argument-order.test.ts`. Code documented in the CLI README, "Diagnostics".
* **`resolve` is typed.** `vlx check`, `dev` and `build` write `.valance/types/library-components.d.ts`, the qualified ids (`package/name`) of the library components `src/main.ts` lists, into `@valancex/common`'s new `LibraryComponentIds`; `resolve` takes a `ResolveId`, one of them, and any string while there are none. Written before the compile, so it is there when a collision stops it. Test: in `packages/cli/test/library.test.ts`, "the qualified ids are written as a type".

Audit I2 for the Valance column: Partial, unchanged. The stringly `invoke` key and `resolve` id are typed, and the by-position filling of a bare command's input is warned about but stays (the refinements' B4, a Nexus change, is the other half of I2 ◐ to P).

**Upgrading.** Nothing is required. A literal `invoke` key the table lacks no longer compiles: it was always `UnmappedCommand` at run time, so write it as a `string` if that is what a test means (`packages/valance/test/entry.test.ts` does). For a typed `resolve` in a project made before 0.16, add `".valance/types/*.d.ts"` to `include` in `tsconfig.json` (`vlx init` now writes it).
