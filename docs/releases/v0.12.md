# VALANCE v0.12 release notes

## v0.12.0

*Prepared 2026-10-14 (nothing tagged or published: v0.11.0 is the latest release).* A minor release of four packages that share one version and are published together, in this order: `@valancex/valance`, `@valancex/common`, `@valancex/cli`, `@valancex/router`. Before 1.0 a minor is a new range.

| Package | Is | Stability |
|---|---|---|
| `@valancex/valance` | The composition boundary: three small security changes, and two route-table seams | Stable, with the changes below |
| `@valancex/router` (new) | Routes with typed path and query parameters, guards (`canMatch`, `canActivate`, `canDeactivate`, `beforeEach`), programmatic navigation and a title per route; plugs into `Web.run` | **Provisional** |
| `@valancex/common` | Titles, viewport, announcements, an `Http` capability with interceptors, and the headers a built site ships with | Provisional, as before |
| `@valancex/cli` | `vlx generate`, `vlx sync`, `vlx help`; a strict `_headers`; the vocabulary as a value | Provisional, as before |

`@valancex/common`, `@valancex/cli` and `@valancex/router` depend on `^0.12.0` of `@valancex/valance`.

### VALANCE

- **`vlx init --desktop` (new, unreleased tier): the desktop target.** One target per project (`valance.desktop.json` marks it; the wizard now asks for one, and `--yes` means the web). Templates are checked against the Desktop PORT's vocabulary, with its own built-in layout and views, so a `<div>` is an error from `vlx check`. `vlx build` writes `dist/desktop/engine.mjs` (everything bundled) and `mesh-runtime.wasm`; `vlx dev` opens the PORT's `vlx-window` on it and opens it anew on each change. The engine's entry is `@valancex/common/desktop`.
- **`@valancex/valance/native` (new, unreleased tier): `Native.run`.** The engine side of a native application, as `Web.run` is for a page: `await Native.run(app, { titleOf, mayClose, onLink })` serves the application on stdin and stdout for the Desktop PORT's window. The window's title is the application's (`titleOf`), closing asks the application (`mayClose`), a link is an address the application interprets (`onLink`), and the application's log goes to stderr because stdout is the protocol. Contract §20.

- **A title is plain text.** The document's title (from `titleOf` or `head`), every meta `content` and every link `title` has control characters and the bidirectional override and isolate characters (U+202A to U+202E, U+2066 to U+2069) removed, whitespace collapsed, and a title cut at 200 characters, on the server (`renderHead`) and in the browser (`applyHead`, `titleOf`). Those characters let a string reorder or hide what is around it in a tab, a history list or a window switcher, which is a spoofing vector as soon as a title comes from user data. A title that is already the document's is no longer written again. New exports from `@valancex/valance/web/plugin`: `cleanTitle`, `plainText`, `TITLE_LIMIT`.
- **The log of a failed start-time command no longer carries what the failure carried.** The message is still `start-time work failed`; it now has an annotation `failure` with the failure's `_tag`, `code` or `name` (else `failure` or `defect`), and nothing else. The whole cause goes to the new `StartOptions.onStartFailure(cause)` (also in `RunOptions`), if the application passes one. Before, a bearer token inside an error reached the log. *This changes the content of a Stable log line*, which is why it is in a minor.
- **Two route-table seams.** `RouteTable.modeOf` (push or replace per transition) and `RouteTable.guard` (asked before a link, Back or Forward leaves; it answers yes, no or a redirect on the origin; a refusal is undone with `history.go`). The history keeps its position in `history.state`. A table that declares neither behaves as before.

### `@valancex/router`

- `createRouter({ routes, base, context, beforeEach, notFound })` gives a route table (`router.plugin` for `Web.run`) and `router.commands(state)` (`navigate`, `go`, `replace`). Parameters and query are Schema'd and decoded to JSON-safe values; a guard answers `true`, `false`, a `redirect(name, params, query)` (by route name, never by URL), or a Promise or Effect of those; `safeNext` refuses an off-site return address. `router.enter(address, state)` starts an application on an address after the entering guards (a deep link or restored session); `router.moveTo(state, to)` goes to an address from inside a command with the same decision `go` makes; `router.mayLeave(state)` asks the current route's `canDeactivate` for a close (`kind: "close"`). Not yet: nested routes, a `beforeunload` guard, a `Navigation` capability for other targets.

### `@valancex/common`

- **Interceptors for the `Http` capability.** One shape, `Interceptor = (next: Transport) => Transport`, chained with `chain`; installed for the application with `defineApp({ http: { interceptors } })`, for a piece of work with `withInterceptors(effect, ...)`, or for one request with `interceptors`. `bearer`, `refreshOn401` and `retryGet` ship with the origin guard built in, and the client refuses a request an interceptor moved outside the API's origin. `webHttp({ fetch })` still works; the response is judged after the interceptors, so one sees a 401 or 503 before it becomes an error.
- **A backend.** `@valancex/common/http` is the `Http` capability (`request({ path, response })`) and the web's implementation of it: same-origin by default, JSON in and out, the answer decoded by the Schema you give, bounded in time and size, cancelled with the application, never carrying the answer or the address in a failure. `api` in `valance.web.json` sets the base and, for `vlx dev`, a `proxy`.
- **A title the application can set.** `defineApp({ title: (state, page) => ({ page?, app?, status? }) })`; the project's format in `valance.json` (`"title": "{page} · {site}"`) puts the parts together.
- **`viewport`.** A layout reads `viewport` (`"compact"` under 600 px, `"medium"`, `"expanded"` from 840), kept current by the framework (state field and `resize` command, both reserved names).
- **Page changes are announced.** After the application changes page in place, a polite live region says the new title and focus moves to `#content` when it is focusable. On by default; `"announce": false` in `valance.web.json` turns it off.

### `@valancex/cli`

- **The built-in `heading` view is now `heading-block`**, like `list-block`: `override: [component(heading)]` becomes `component(headingBlock)` with a template named `heading-block.mprx`. The old name collided with a vocabulary that has a `heading` of its own (found drawing a content site natively); 0.11 documented overriding it, so this breaks a project that did.

- **`vlx generate page|component`** (alias `g`), **`vlx sync`** and **`vlx help`**.
- **Security headers.** `vlx build` writes `_headers` with a strict Content-Security-Policy (`script-src 'self' 'wasm-unsafe-eval'`), `nosniff`, a referrer policy, a permissions policy and a cross-origin opener policy. Turn it off with `"headers": false`.
- **The vocabulary is a value.** The build compiles against a `Vocabulary` (the web's by default) instead of importing the web's tag table.
- A link whose address has balanced parentheses is read whole, so the `link-scheme` check quotes all of it.

### VS Code extension

It runs the project's own `vlx check` by itself when a window opens and whenever the project's files change, one run at a time.

### Upgrading

- **From 0.11:** change the versions. If anything reads the start-time failure log for the cause, pass `onStartFailure` instead; if a title carries direction-override or control characters on purpose, they are now removed.
