# VALANCE v0.11 release notes

## v0.11.0

*Prepared 2026-10-14 (nothing tagged or published: v0.10.0 is the latest release).* A minor release of three packages that share one version and are published together, in this order:

| Package | Is | Stability |
|---|---|---|
| `@valancex/valance` | The composition boundary over NEXUS, MESH and PORT | Stable, as before |
| `@valancex/router` (new) | Routes with typed path and query parameters, guards (`canMatch`, `canActivate`, `canDeactivate`, `beforeEach`), programmatic navigation and a title per route; plugs into `Web.run` | **Provisional** |
| `@valancex/common` (new) | What an application's `src/main.ts` imports (`defineApp`, `component`, `field`), and the runtime a built application runs | **Provisional** |
| `@valancex/cli` (new) | The `vlx` command: make, serve, build, check, sync and extend an application | **Provisional** |

**`@valancex/valance` changes in three small ways, all of them security fixes** (below, under "VALANCE"); an application that does none of the things they touch behaves as before. The minor also gives the three packages one version and one tag (`v0.11.0`, [`release.yml`](../../.github/workflows/release.yml)); `@valancex/common` and `@valancex/cli` depend on `^0.11.0` of it. Before 1.0 a minor is a new range.

### VALANCE

- **A title is plain text.** The document's title (from `titleOf` or `head`), every meta `content` and every link `title` has control characters and the bidirectional override and isolate characters (U+202A to U+202E, U+2066 to U+2069) removed, whitespace collapsed, and a title cut at 200 characters, on the server (`renderHead`) and in the browser (`applyHead`, `titleOf`). Those characters let a string reorder or hide what is around it in a tab, a history list or a window switcher, which is a spoofing vector as soon as a title comes from user data. A title that is already the document's is no longer written again. New exports from `@valancex/valance/web/plugin`: `cleanTitle`, `plainText`, `TITLE_LIMIT`. *Probe:* before, `<title>… ‮ evil</title>` reached the document unchanged.
- **The log of a failed start-time command no longer carries what the failure carried** (the open P2 finding in `examples/docs-verifier/docs/PRINCIPLES.md`). The message is still `start-time work failed`; it now has an annotation `failure` with the failure's `_tag`, `code` or `name` (else `failure` or `defect`), and nothing else. The whole cause goes to the new `StartOptions.onStartFailure(cause)` (also in `RunOptions`), if the application passes one. Before, a bearer token inside an error reached the log. *This changes the content of a Stable log line*, which is why it is in a minor.

### What `vlx` is

`vlx` is the way into Valance: it makes an application (`vlx init`), serves it as you edit (`vlx dev`), builds the static site (`vlx build`), checks it (`vlx check`), refreshes the generated files (`vlx sync`) and adds to it (`vlx generate`). An application is Markdown content, a layout, components and styles; the project writes no compiler step, manifest, server, hydration script or bundler configuration. The root README starts there, and [`packages/cli/README.md`](../../packages/cli/README.md) is the guide.

### `@valancex/router`

- **A dedicated router.** `createRouter({ routes, guards })` gives a route table (`router.plugin` for `Web.run`) and `router.commands(state)` (`navigate`, `go`, `replace`). Parameters are Schema'd and decoded to JSON-safe values; a guard answers `true`, `false`, a `redirect(name, params, query)` (by route name, never by URL), or a Promise/Effect of those; `safeNext` refuses an off-site return address.
- **Two engine seams in `@valancex/valance`.** `RouteTable.modeOf` (push or replace per transition) and `RouteTable.guard` (asked before a link, Back or Forward leaves; a refusal undoes the move with `history.go`). A table that declares neither behaves as before.

### `@valancex/common`

- **Interceptors for the `Http` capability.** One shape, `Interceptor = (next: Transport) => Transport`, chained with `chain`; installed for the application with `defineApp({ http: { interceptors } })`, for a piece of work with `withInterceptors(effect, ...)`, or for one request with `interceptors`. `bearer`, `refreshOn401` and `retryGet` ship with the origin guard built in, and the client refuses a request an interceptor moved outside the API's origin. `webHttp({ fetch })` still works; the response is judged after the interceptors, so one sees a 401 or 503 before it becomes an error.

- **The authoring API moved out of the command line package.** `src/main.ts` imports `defineApp`, `component` and `field` from `@valancex/common`, and `Schema` from `effect`. `Schema` is no longer re-exported.
- **The runtime a built application runs moved with it.** The browser and server entries the build generates (`@valancex/common/client`, `/server`), the content model, the routes, the scope a layout reads, the state and the tag table now live in `@valancex/common`; `@valancex/common/internal` shares them with the build tools. A built or deployed application depends on `@valancex/common` alone. `@valancex/cli` is a development tool: a new project has it as a dev dependency, and it no longer brings the terminal interface, Vite or the MESH compiler into the application's dependencies.
- It depends on `@valancex/valance`, `@valancex/mesh-runtime` `^0.11.0` and `@valancex/port-web` `^0.4.0`, with `effect` a peer. `@valancex/common`'s authoring entry has no Node, bundler or terminal import (a test checks it).

### Changes in the application model

- **`components` replaces `uses`.** A component is registered once, in `defineApp({ components: [...] })`. Which components a template uses is read from the template, so the per-component `uses` list, and its errors (`component-undeclared`, `component-unused`), are gone. A file under `src/` that is not registered is still `template-unused`. A registered component that no template writes yet is not part of the program, and is not an error.
- **A title the application can set.** `defineApp({ title: (state, page) => ({ page?, app?, status? }) })`: `status` is written first, in parentheses (an unread count); the project's format in `valance.json` (`"title": "{page} · {site}"`) puts the parts together. See the CLI guide.
- **`viewport`.** A layout reads `viewport` (`"compact"` under 600 px, `"medium"`, `"expanded"` from 840), kept current by the framework (state field and `resize` command, both reserved names). The server renders `expanded`; the browser corrects it as it starts. A layout adapts with `{#if viewport == "compact"}`.
- **Page changes are announced.** After the application changes page in place, a polite live region says the new title and focus moves to `#content` when it is focusable; a link to a `#heading` is left to the browser. On by default; `"announce": false` in `valance.web.json` turns it off.
- **A backend.** `@valancex/common/http` is the `Http` capability (`request({ path, response })`) and the web's implementation of it: same-origin by default, JSON in and out, the answer decoded by the Schema you give, bounded in time and size, cancelled with the application, never carrying the answer or the address in a failure. `api` in `valance.web.json` sets the base (a path, or an absolute https address) and, for `vlx dev`, a `proxy`.
- **Security headers.** `vlx build` writes `_headers` with a strict Content-Security-Policy (`script-src 'self' 'wasm-unsafe-eval'`: the runtime is WebAssembly, and without that source the page never starts), `nosniff`, a referrer policy, a permissions policy and a cross-origin opener policy. Turn it off with `"headers": false`. The site's own browser test runs under the written policy.
- **The vocabulary is a value.** The build compiles against a `Vocabulary` (the web's by default) instead of importing the web's tag table; each target carries one. A test runs the project `vlx init` makes on a second, non-DOM target unchanged, and records which props are the web's (`class`, `theme`, `id`, `tabindex`, `label`, `current`, `pressed`, `loading`).
- **Slots** (`<mesh-slot />`, `<mesh-slot name="…" />`, `<mesh-fill slot="…">`) work in components and are documented in the CLI guide.

### Commands

- A link whose address has balanced parentheses (`javascript:alert(1)`) is read whole, so the `link-scheme` check quotes all of it.

- **`vlx generate page <path>` and `vlx generate component <name>`** (alias `g`): add a Markdown page, or a component (`src/<name>.mprx`, `src/<name>.ts`) imported and registered in `src/main.ts`. Nothing is overwritten.
- **`vlx sync`** brings `.valance/` (the template types, the manifest, the entries) up to date and never fails. A new project runs it by itself after install (its `prepare` script) and before `typecheck`; `vlx generate` runs it after it writes; `dev`, `build` and `check` already did.
- **`vlx help [command]`**, and `--help` for every command.
- `vlx init` writes a `tsconfig.json` (it documented one and did not write it), so typed template imports and `typecheck` work in a new project, and it writes the new dependencies: `@valancex/common` and `effect`, with `@valancex/cli` as a dev dependency.

### The VS Code extension (not published)

It runs the project's own `vlx check` by itself when a window opens and whenever a content, template, code or settings file is created, changed, deleted or saved, one run at a time, and tells the language server after each run, so nothing has to be run by hand first. The `valance.check.onType` setting, which was never implemented, is gone.

### Upgrading

- **From the workspace versions of the tooling** (none was published): replace `import { component, defineApp, field, Schema } from "@valancex/cli"` with `import { component, defineApp, field } from "@valancex/common"` and `import { Schema } from "effect"`; list every component in `components` and delete each `uses`; put `@valancex/common` and `effect` in `dependencies` and `@valancex/cli` in `devDependencies`.
- **From `@valancex/valance` 0.10:** change the version. If anything reads the start-time failure log for the cause, pass `onStartFailure` instead; if a title carries direction-override or control characters on purpose, they are now removed.
